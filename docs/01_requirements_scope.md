# 第一步成果：业务需求与项目范围

项目：淘宝展示广告投放表现分析数仓系统的设计与实现

版本：V0.2，数据范围表述已确认，整体待用户审核

编制日期：2026年11月15日

本文件用于确定项目要解决的问题和建设范围。审核通过后，再编制正式指标字典、设计数据模型和实现ETL。文中“拟实现”不表示功能已经完成。

## 1. 项目背景

电商展示广告运营需要了解不同广告计划、广告主、用户群体、资源位和时段的曝光与点击表现。原始日志分散在曝光点击记录、广告信息和用户画像文件中，直接分析容易出现字段不统一、关联丢失、统计口径不一致等问题。

本项目使用阿里云天池公开的淘宝展示广告点击率预估数据集，建设面向历史投放表现分析的离线数据仓库。通过数据检查、维度建模、分层ETL和可视化，将原始记录转化为可查询、可复查的样本分析结果，为识别投放表现差异、安排后续投放测试提供依据。

项目关注历史曝光到点击的表现。数据集名称中的“预估”是任务背景，本项目不以训练点击率预测模型作为主体目标。匿名编码用于分组分析，不补造真实广告主、品牌或类目名称。

## 2. 分析使用者与目标

以下是课程项目设定的业务角色，不代表已经与真实企业用户开展需求访谈。

| 使用者 | 关注的问题 | 系统应提供的支持 |
| --- | --- | --- |
| 广告运营人员 | 样本投放总体表现如何，日期和资源位之间有什么差异 | 查看概览、趋势及资源位比较结果 |
| 广告投放优化人员 | 哪些广告计划、广告主、类目值得进一步观察 | 比较曝光、点击贡献和点击率，并同时查看样本量 |
| 人群分析人员 | 不同画像群体对广告的响应有何差异 | 比较各群体表现，展示未知群体和画像覆盖情况 |
| 数仓开发与维护人员 | 数据是否完整、关联是否正确、结果能否复现 | 查看导入与处理记录、质量检查及分层总量核对结果 |

## 3. 业务分析需求

| 编号 | 主题 | 需要回答的问题 | 拟提供的分析结果 | 使用边界 |
| --- | --- | --- | --- | --- |
| R01 | 投放概览 | 在选定数据范围内，总体曝光、点击和用户触达如何，是否随日期变化 | 曝光量、点击量、点击率、触达用户数和日趋势 | 全量与开发样本明确标注，不外推淘宝全平台 |
| R02 | 广告表现 | 按广告计划、广告主、商品类目和品牌等维度，比较曝光量、点击量和点击率的差异。 | 分组比较、曝光与点击贡献、可切换指标的排行 | 比较点击率时同时展示曝光量；匿名编码不编造名称 |
| R03 | 人群分析 | 不同性别编码、年龄层次、购物深度等群体响应有何差异 | 分群曝光、点击、点击率及画像覆盖信息 | 未匹配画像与属性缺失分别保留；编码含义经核实后展示 |
| R04 | 资源位与时段 | 不同资源位、日期和小时的曝光与点击分布如何 | 资源位比较、小时分布、日期与资源位交叉分析 | 使用统一分析时区；比较反映观察差异，不证明因果效果 |

本步只确定指标名称和用途。公式、统计范围、可加性、分母为零处理等在下一步指标字典中统一规定。

## 4. 数据范围

本项目主体使用广告曝光点击日志、广告信息和用户画像，建设曝光到点击的投放表现分析数仓。用户历史行为日志作为扩展数据源，待完成数据核查、历史窗口定义和关联方案设计后，再评估是否纳入。

官方数据集入口：https://tianchi.aliyun.com/dataset/56

下表规模来自本项目已生成的 `output/data_check/audit.json`，是现有本地解压文件的核查结果。

| 数据表 | 已核查规模 | 主体用途 | 状态 |
| --- | ---: | --- | --- |
| raw_sample | 26,557,961条 | 广告曝光与点击分析 | 已全量核查，拟用于正式主体ETL |
| ad_feature | 846,811条 | 广告、计划、广告主、类目、品牌等属性 | 已全量核查，拟保留全表 |
| user_profile | 1,061,768条 | 用户画像分组 | 已全量核查，拟保留全表 |
| behavior_log | 实际总行数未核实 | 可选的历史购物行为扩展 | 仅检查包内元数据及开头记录，尚未纳入主体 |

主体业务时间按UTC+08:00转换后为2017年5月6日至13日，共8天。保存原始Unix时间戳，明确UTC+08:00为项目采用的分析时区。数据属于历史样本，不以下载或上传日期代替业务日期。

开发阶段拟使用覆盖8天的可复现曝光样本，同时保留完整广告表和画像表，所有成员使用同一版本。抽样方法、数量和种子尚未确定，不将文件前若干行视为随机样本。正式主体ETL以全量广告日志为目标，如需缩小范围，先记录并审核调整。

行为日志是否纳入、筛选用户范围和历史时间窗口，待主体流程与资源验证后决定。不得将其官方说明中的总体规模写成项目已处理规模，也不直接将购物行为认作广告成交。

## 5. 系统功能范围

| 编号 | 功能 | 本项目拟实现的内容 |
| --- | --- | --- |
| F01 | 数据接入与追溯 | 识别来源文件、记录导入批次和处理范围，保留源记录追溯信息 |
| F02 | 数据清洗与质量检查 | 统一字段、校验标签与时间、检查缺失和重复、核对维度关联覆盖率 |
| F03 | 分层加工 | 实现ODS、DIM、DWD、DWS、ADS间的数据加工，明确各层职责 |
| F04 | 多维统计 | 支持按日期、广告属性、用户画像、资源位和时段分组比较 |
| F05 | 看板展示 | 展示概览、趋势、排行、分群比较；支持日期和必要业务维度筛选 |
| F06 | 校验与复现 | 核对关联前后记录数和各层曝光、点击总量，保留运行日志与执行说明 |

本项目为离线分析系统。中期先形成真实样本的完整加工流程和初步分析，最终实现再扩大至约定正式数据范围。

## 6. 已发现的数据问题及需求影响

| 核查发现 | 对系统需求的影响 |
| --- | --- |
| 实际未点击字段为nonclk，广告主字段为customer，画像末列名有尾随空格 | 保存源字段信息，在清洗层建立明确命名映射 |
| 广告表和画像表关联键均无重复；广告信息行覆盖率100% | 关联前保留唯一性检查，后续导入不能默认一直满足 |
| 1,528,526条曝光记录无法匹配画像，涉及79,961名用户 | 以曝光为基准保留记录；展示未匹配画像群体及覆盖率 |
| 画像表消费档次缺失54.24%，城市等级缺失32.49% | 保留未知属性，不以预测值冒充观测属性；分析时注明缺失影响 |
| 广告日志未发现六列完全相同的重复行，但用户加时间戳存在大量重复 | 不按用户加时间戳去重；使用来源文件与源行号等信息追溯记录 |
| 行为日志开头出现pv | 行为编码须在实际数据核查后映射，暂不沿用背景中的ipv写法 |

## 7. 范围边界与质量要求

- 本轮主体分析不包含CTR预测模型、广告实时投放或自动调整功能。
- 无广告花费、归因订单金额，不能计算真实CPC、CPM、ROI、ROAS，也不能用商品价格推算成交额。
- 不能为匿名类目或品牌直接套用其他数据集名称映射，除非存在经过验证的对应关系。
- 点击率比较体现观察到的表现差异，不将其表述为某项调整的因果效果或保证收益。
- 关联不能意外放大或丢弃曝光；汇总结果必须与明细曝光和点击总量核对。
- 全量数据结果、抽样结果和官方描述规模分开记录；去重用户数不能跨组简单相加。
- 处理代码、配置示例、运行说明和检查结果应可供组员复现；不将账号密码提交到代码仓库。

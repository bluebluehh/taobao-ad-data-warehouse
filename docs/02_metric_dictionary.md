# 第二步成果：指标字典与统计口径

项目：淘宝展示广告投放表现分析数仓系统的设计与实现

版本：V0.1，待用户审核

编制日期：2026年11月15日

前置状态：用户已在本轮同意进入下一步，第一步“业务需求与项目范围”按审核通过处理。第一步文件中的待审核文字是此前版本的状态快照，以本轮确认记录为准。本文件制定指标口径，不表示相应ETL、结果表和看板已经实现；用户审核后再进入模型设计。

## 1. 本步目的

指标字典统一回答：每个指标是什么意思、使用哪些记录、怎样计算、可以按哪些维度查看，以及合并分组时能否相加。四个业务主题共享同一套定义，不能各自编写不同口径。

主体仍为raw_sample、ad_feature、user_profile三张表，behavior_log保持扩展定位。字段名在本文件中用于说明公式，后续模型设计再确定物理表名、类型和键。

## 2. 共同统计范围

### 2.1 有效曝光记录

一条通过以下检查的源广告日志计为一次样本曝光：

1. 字段数正确，用户ID、广告单元ID、资源位及时间戳不缺失。
2. 时间戳可转换，并位于所选数据版本的约定业务日期范围内。
3. 点击标签组合为(nonclk,clk)=(1,0)或(0,1)。

不满足条件的记录保留在ODS及异常记录清单中，不进入正式指标分母；记录排除原因与数量。当前全量检查没有发现字段缺失、字段数异常、时间戳解析失败或非法标签。业务期为2017年5月6日至13日，采用UTC+08:00分析时区，并保留原始时间戳。

维度匹配失败不等于曝光无效：以曝光为基准左关联，未匹配信息进入未知成员。维度键不唯一时应先报错并解决，不允许任意取一条或直接关联后继续统计。

当前日志没有六列完全相同的重复行。不能按用户加时间戳去重；未来出现相同字段记录也先检查来源，不擅自删除。重复导入同一源文件中的同一行属于技术重放，应通过来源追溯防止重复入仓，不作为新曝光。

### 2.2 筛选集合与分组集合

用S表示本次查询经过数据版本、日期和业务筛选后得到的有效曝光集合，用G表示S中的某个分组。分组可以是广告计划、年龄层次，也可以是广告计划与年龄层次的组合。

- 开发样本与全量版本分开统计，不能叠加；同一条源记录不因出现在两个版本而计两次。
- 多日查询按所选日期整体计算。界面日期区间首尾日期均包含，内部按起始日00:00至结束日次日00:00的左闭右开范围实现。
- 默认包含未匹配维度和属性缺失分组；用户主动筛选已知群体时，所有指标只描述筛选后的群体，并显示筛选条件。
- 空白和NULL视为缺失；原始编码0不能未经官方说明就当作缺失。缺失画像整行与已匹配画像但某个属性为空必须区分。
- ID作为标识使用，不因转为数值或显示名称而改变其身份；各类编码说明核实后再展示。

## 3. 核心业务指标

以下公式均在当前集合S或其分组G中计算。COUNT DISTINCT表示对实际用户或广告业务ID精确去重，不将维度“未知成员键”当作真实用户或真实广告ID。

| 编号 | 指标名称与建议代码 | 定义及计算公式 | 单位 | 汇总规则 |
| --- | --- | --- | --- | --- |
| M01 | 曝光量 impressions | 有效曝光记录数COUNT(*) | 次 | 可在互不重叠且完整划分的曝光分组之间相加 |
| M02 | 点击量 clicks | 有效曝光记录的SUM(clk) | 次 | 同上；不是去重点击用户数 |
| M03 | 点击率 ctr | clicks / impressions | 比率 | 不可相加，也不能直接平均各组点击率；先汇总分子分母再计算 |
| M04 | 触达用户数 reached_users | 有效曝光中COUNT(DISTINCT user_id) | 人 | 不可跨日期、广告等直接相加；按目标范围重新去重 |
| M05 | 点击用户数 clicked_users | clk=1的有效曝光中COUNT(DISTINCT user_id) | 人 | 不可直接相加；一名用户点击多次仍计1人 |
| M06 | 用户点击比例 user_click_rate | clicked_users / reached_users | 比率 | 先按目标范围分别去重，再相除；与按曝光计算的点击率不同 |
| M07 | 曝光广告单元数 exposed_ads | 有效曝光中COUNT(DISTINCT adgroup_id) | 个 | 不可跨日期、资源位等直接相加；不是广告信息表总行数 |
| M08 | 人均曝光次数 avg_impressions_per_user | impressions / reached_users | 次/人 | 汇总时重算目标范围曝光量和去重用户数，不平均各组结果 |
| M09 | 曝光贡献率 impression_share | impressions(G) / impressions(S) | 比率 | 分母为相同筛选条件下、分组前集合S的曝光量 |
| M10 | 点击贡献率 click_share | clicks(G) / clicks(S) | 比率 | 分母为相同筛选条件下、分组前集合S的点击量 |

M01—M04是概览必备指标。M05—M08用于补充用户响应和覆盖分析，M09—M10用于排行及贡献分析。M06界面使用“用户点击比例”，避免与M03都简称为点击率。

### 3.1 贡献率的分母规则

贡献率回答“当前分组占当前分析范围的多少”。先执行业务筛选形成S，再分组计算G，最后截取Top N用于展示。

- 在某一天、某资源位中比较广告计划，各计划贡献率分母为这一天、这个资源位的总量。
- Top 10截取不能改变分母，不能把Top 10内部占比冒充总体贡献率。可添加“其他”以展示剩余贡献。
- 当完整分组互斥且穷尽S时，曝光贡献率合计为100%；总点击量大于0时，点击贡献率也合计为100%。显示舍入可有微小误差。
- “点击用户贡献率”不在本版指标中。用户可同时属于多个广告计划，不能套用可加的点击量贡献率理解。

### 3.2 计数可加的条件

可加不是指任意结果表都能相加。例如按天的曝光汇总可以合并为8天总曝光，但同一批曝光的“按天汇总”和“按广告汇总”不能再相加，否则重复计算。汇总来源及覆盖粒度必须一致。

## 4. 数据质量指标

质量指标与业务指标分开显示。缺失属性保留未知；为了让覆盖率有解释力，其默认统计范围为画像筛选前的有效曝光集合S0，可包含日期、广告、资源位等筛选。看板明确显示质量指标使用的范围，不让性别等画像筛选把覆盖率自然筛成100%后误导读者。

| 编号 | 名称 | 公式与分母 | 用途 |
| --- | --- | --- | --- |
| Q01 | 画像行关联覆盖率 | S0中匹配到用户画像的曝光记录数 / S0曝光量 | 衡量多少曝光能够关联到画像，不要求每个画像属性都完整 |
| Q02 | 画像用户关联覆盖率 | S0中匹配到画像的去重用户数 / S0触达用户数 | 按人衡量覆盖情况，与按曝光计算的Q01不同 |
| Q03 | 广告行关联覆盖率 | S0中匹配到广告信息的曝光记录数 / S0曝光量 | 监测广告属性可用性 |
| Q04 | 已匹配曝光的画像属性缺失率 | S0中已匹配画像但指定属性为空的曝光记录数 / S0中已匹配画像的曝光记录数 | 衡量已匹配群体中某字段可用程度；每个字段单独计算 |

Q04不包含整行画像未匹配的曝光，后者由Q01反映。画像已匹配也不能把属性空白填成某个真实类别。

源表核查另有“画像源表属性缺失率”：画像表该字段为空的用户记录数 / 画像表总用户记录数。它按画像表用户计数，不按曝光加权，不能直接填入Q04。

## 5. 支持的维度及组合

| 维度组 | 本版分析属性 | 适用指标与约束 |
| --- | --- | --- |
| 时间 | 日期、小时 | M01—M10；小时默认指所选日期内同一小时段汇总，按日期加小时可查看具体时段 |
| 广告 | 广告单元、计划、广告主、商品类目、品牌 | M01—M10；属性由广告维度提供，编码不翻译为未经验证的名称 |
| 用户画像 | 性别编码、年龄层次、购物深度、消费档次、是否大学生、城市等级 | M01—M10；编码含义核实后展示，未知群体保留 |
| 投放场景 | 资源位 | M01—M10；资源位编码不补造真实页面位置 |
| 交叉分析 | 广告计划与年龄层次、资源位与广告计划、日期与资源位等 | 沿用同一公式；根据记录实际归属分组，不额外制造维度组合 |

四个主题共享指标，而非限制指标只能出现在某一个页面。广告属性之间存在归属关系，模型设计阶段检查实际关系后确定下钻路径；不会将广告主、计划、类目、品牌强行串成未经验证的单一层级。

多维分组提高观察的细致程度，不等于随机实验或因果识别。交叉越细，样本量越小，因此所有CTR比较至少同时展示曝光量和点击量。

## 6. 空值、精度与排序

| 情况 | 统一规则 |
| --- | --- |
| 有曝光但无点击 | 点击量0，CTR为0；点击用户数及用户点击比例为0 |
| 查询范围无曝光 | 曝光、点击、去重用户和广告数均为0；比率和人均曝光为NULL，界面显示“—”并提示无有效曝光 |
| 当前范围总点击为0 | 各组点击贡献率为NULL，不写0%来暗示存在可分配点击 |
| 画像完全未匹配 | Q01、Q02为0（范围内有曝光）；Q04因分母为0显示“—” |
| 百分比 | 内部保存0到1的数值，除法使用非整数除法；展示时乘100，默认两位小数 |
| 人均曝光 | 内部保留计算精度，展示默认两位小数 |
| 计数 | 使用足够容量的整数类型，原始值精确保存，界面千分位展示 |
| 舍入 | 仅在最终展示舍入；CTR排行使用舍入前结果，不能先舍入再排名 |
| 排行默认规则 | 默认按点击量降序，曝光量降序，业务ID升序；CTR排行按CTR降序、曝光量降序、业务ID升序 |
| 小样本CTR排行 | 拟设置可调整的最小曝光量门槛，初始建议1000次；这是项目展示规则，不是统计显著性标准。该门槛只影响排名资格，不改变贡献率的总体分母；不足N个合格对象时显示实际数量 |

不以展示0%的方式掩盖未定义的比率。所有看板至少标明数据版本、业务日期范围、分析时区、当前筛选条件；开发样本页面明确注明样本结果。

## 8. 后续实现必须通过的核对

1. 本数据版本源行数=有效行数+异常排除行数，原因计数去重后与异常总量一致；重放导入不重复计入。
2. 维度关联前后有效曝光行数相等；点击总量不变，未知维度记录仍保留。
3. 所有分组均满足0<=点击量<=曝光量；0<=点击用户数<=触达用户数<=曝光量。
4. 对完整互斥分组，曝光量、点击量之和等于所对应筛选范围的明细总量。
5. 上卷后的CTR由汇总点击和曝光重新计算；UV、点击用户数和广告数在目标范围精确去重。
6. 贡献率在完整分组中的和按其分母规则核对；Top N截取前后分母不变。
7. 画像行匹配量加未匹配量等于有效曝光量；画像源表缺失率与曝光加权缺失率分别记录。
8. 核对无记录、零点击、缺失画像、多日筛选及样本切换等边界。此处是后续验证要求，不声称本轮已完成ETL测试。
